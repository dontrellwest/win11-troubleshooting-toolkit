RUN FROM N-CENTRAL
=================

WHERE THIS RUNS
--------------
  - The PS1 runs on each selected Windows endpoint through its agent.
  - Do not run it once on the N-central server/probe and expect a fleet list.
  - Use the PS1, not the interactive CMD. No RSAT or WinRM is needed locally.

RUN THE INVENTORY
-----------------
  1. Select the customer/site or organization scope you intend to check.
  2. In Configuration > Scheduled Tasks > Script/Software Repository, upload
     02-Find-Windows-10-Computers.ps1 as a scripting task script.
  3. Use Configuration > Scheduled Tasks > Add/Delete > Add > Scripting.
     Select that script and supply these command-line parameters:
       -Mode Local -OutputFormat Json
  4. Supply the correct customer/site labels for reports you will merge:
       -CustomerName "Example Customer" -SiteName "Main Office"
     Use separate customer/site target groups for fixed labels. Do not label
     a multi-customer task with one customer's name.
  5. On Targets, select ALL intended managed Windows devices. Do not rely
     only on an old Windows 10 inventory filter; it can miss outdated records.
  6. Run once using the agent's usual LocalSystem/device execution context.
     Test on one Windows 10 and one Windows 11 PC before the full group.
  7. Review task status/output for every target. Retry offline, expired,
     denied and failed tasks. No returned result is not an upgraded PC.

  - Newer N-central releases also have Views > Scripting/Assets execution
    views. Menu names vary; the classic scheduled scripting route above is
    documented for PS1 files and selecting multiple targets.
  - Script output is JSON. Local success returns normally for either OS;
    inspect Windows10Count/IsWindows10, not just the task's success icon.

GET ONE COMBINED LIST
--------------------
  - Each endpoint saves its raw .win10.json in C:\Temp\Toolkit\Windows10.
  - Retrieve those files using your normal remote file-transfer method into
    one folder on your technician PC. Keep their unique filenames.
  - Alternatively save this script's raw JSON output as a .win10.json file.
    A downloaded N-central task-output wrapper is not the raw report: extract
    the script's JSON first. The merge rejects unknown formats.
  - Save the intended short computer names, one per line, as PCs.txt.
    Use one customer/site/domain per merge with this expected list.
  - From PowerShell in this tool's folder:
      $tool = '.\02-Find-Windows-10-Computers.ps1'
      $options = @{Mode='Merge'; InputFolder='C:\Temp\Win10Reports'}
      $options.ExpectedListPath = 'C:\Temp\PCs.txt'
      & $tool @options -Display
  - Read Windows10-Names.txt and Windows10.csv. Unknown.csv includes stale,
    failed or missing endpoint reports. Newest report wins per named device.
  - Imported results are snapshots; default maximum age is 7 days.
  - Conflicting device identities or equally dated OS results become Unknown.
  - Without an expected list, the summary cannot account for missing devices.

FAST EXISTING-INVENTORY ALTERNATIVE
---------------------------------
  - N-central's All Devices/Assets inventory can be filtered for Windows 10
    and exported. That gives a quick recorded-inventory list, including
    offline devices, but its OS information may predate an upgrade.
  - Use this script to verify the actual OS. Keep customer/site, check time
    and task failures with any list you use for upgrade planning.

  N-central UI execution has not been tested from this project laptop.
